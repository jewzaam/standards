# PowerShell 5.1 Scripts

Rules for scripts that must run on Windows PowerShell 5.1.

## Keep source ASCII

Save `.ps1` files ASCII, no BOM, no smart punctuation (em dash, middle dot,
curly quotes). 5.1 reads BOM-less files as the ANSI code page and corrupts
anything else.

## Parenthesize ConvertFrom-Json before piping

`ConvertFrom-Json` emits a JSON array as one object, so the pipeline sees a
single item.

```powershell
# Bad: Sort-Object receives one item (the array)
$json | ConvertFrom-Json | Sort-Object name

# Good
($json | ConvertFrom-Json) | Sort-Object name
```

## Variable names are case-insensitive

`$b` and `$B` are the same variable. Do not shadow a parameter with a local
differing only by case.

## Never patch files through an interpreter heredoc

Do not edit files by piping a heredoc to an interpreter with ordinary
escape-processing string literals (`python -`, etc.): `\U`, `\n`, `\b` are
interpreted and silently mangle the content. Use an edit tool, or raw
strings inside a script file.

## Data files: BOM-less UTF-8

Write data files that scripts read back with a BOM-less encoding:

```powershell
[IO.File]::WriteAllLines($path, $lines, (New-Object Text.UTF8Encoding($false)))
```

`Set-Content -Encoding utf8` adds a BOM in 5.1, which breaks consumers that
split the file into paths or parse it as JSON.

## When to apply

Any script or tool intended to run under `powershell.exe` 5.1, including
those generated by agents.
